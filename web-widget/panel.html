▶How the doors workreference

Three tiers, each including the ones below it:

  • Admin — always exists. Opens this panel, the keys and the test buttons; also opens the phone. Set under Access below.
  • Guest — an optional code you hand out that opens the phone. No username; expires per device if you set a clock; the card offers a lock button to forget it early.
  • Open — no code: anyone who can load the page can call, inside the usage caps. On an open line the guest door is off — the code does not elevate — while the admin password still opens everything.

What stands behind them:

  • Passwords — stored as PBKDF2 hashes, never plaintext.
  • Lockouts — wrong guesses are rate-limited fail2ban-style: 5 wrong tries puts the address in a 5-minute cooldown, and a second round of 5 bans it until the app restarts. A restart clears bans, and CALLIN_ADMIN_KEY in the environment is the recovery override.
  • API keys — write-only: the panel shows last-four, never the key.
  • Join tokens — signed and short-lived, minted per call.
  • Caller tier — rides inside the signed token, so a caller cannot raise their own.
  • Station tools — a hard allowlist; the destructive ones are never on the line at any setting.

▶Station

Station admin credentials optional

The line works without these — the DJ can talk, take requests and search the library. They are recommended because they are what unlocks the rest: putting messages on air, running segments, firing a programme beat, skipping a track, putting a different show on air, the back-to-air mention, exact-track queueing, and mirroring each persona's voice from the station. Without them those stay switched off however you set the permissions. Stored server-side, never shown back.

▶Ears
Two real ways to hear:
  • Built-in Whisper — runs in this container; no key, no network, pays in CPU per turn.
  • A cloud ear — word-by-word captions and better accuracy on names, most noticeable from a phone in a noisy room. OpenAI and Google reuse the Brains key; Deepgram takes its own key below and is the most accurate of the three on phone audio.
The built-in models, smallest to largest — each hears better and costs more CPU per turn than the one above it:
  • tiny.en — fastest, hears the least; half the CPU of base
  • base.en — light, the default
  • small.en — hears phone audio clearly better; ~3x base per turn, the practical ceiling on a NAS
  • medium.en — hears the most; ~8x base and seconds of silence per turn — test a call before trusting it
A cloud ear with a key (Deepgram’s phone-call model especially) out-hears all four and costs this box nothing.

Speaks one known line and hears it back — the only check that reaches a cloud ear at all.

            How the DJ finds a record

            Five ways in, and picking the wrong one is how a caller gets told a track isn't here when it is. The DJ is taught this triage in its prompt; the rows above decide which of them it actually has.

            • They named a track or artist — library search. A literal word match on titles and artists, nothing cleverer: one wrong letter finds nothing, so the DJ is told to try the artist alone and correct a misheard title before ever reporting a miss.
            • They described a sound — sound search. Matches the analysed audio rather than the words, so "dreamy and cinematic" comes back with real records instead of songs with "dreamy" in the title. Needs the station's heavy analyzer.
            • They want more of what's on — the station's own neighbours of the current track, with tempo and key.
            • They gave a mood, genre or era — browse. Moods come from the station's fixed vocabulary, so a caller's word for a feeling gets translated rather than matching nothing.
            • They gave nothing to go on — a request, and the station's picker chooses. This is the only one that is rate-limited: the station allows one request at a time per address, and every caller here shares one address.

            Once a record is found, Queue the exact track picked puts that recording in by id — no re-matching, and no request limit. Without it the DJ has to re-submit the title as a request, which can come back with a different recording.

            What the station can do that this line doesn't use

            Kept here on purpose, as the list to work through: the station's liked-tracks and play-history reads, its genre adjacency map, and the library observatory's projection. None are wired to a caller tool yet.
